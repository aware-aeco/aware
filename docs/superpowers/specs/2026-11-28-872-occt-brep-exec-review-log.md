# Plan Review Log: AWARE #872 first slice (OCCT exact B-rep exec)
Started 2026-11-28. MAX_ROUNDS=5. Plan drafted by Codex (builder brief), reviewed adversarially by Codex read-only, Claude arbitrates.

## Round 1 — Codex

**The first slice is too large.** It makes the first real test of the OCCT-to-mesh seam depend on eight operations, a new executable on three platforms, and changes to four distribution paths. The owner explicitly added STEP to #872, so keep both STEP operations in the issue’s acceptance criteria and split implementation into independently gated milestones. [Issue #872](https://github.com/aware-aeco/aware/issues/872) · [November 25 owner ruling](https://github.com/aware-aeco/aware/issues/872#issuecomment-7153904321)

### Smallest slice that proves the seam

Build a **Windows x64 development milestone** with `geometry exec` for `boolean/difference`, indexed tessellation in its result, and the real SHA-256-locked cp312 OCP/VTK runtime with the LGPL text and exception. Run a small dispatcher with the repo-pinned Node and Manifold WASM in a staged test layout. Drive the real CLI against a flush cut at the origin and at a large **member** offset, verify analytic volume and reconstructed placement, then prove that rejecting a computed exact result and running with no runtime both produce a labelled, independently checked mesh cut. Include one flush placement known to stress the mesh path. Gate this milestone in Windows CI. Add STEP read/write next, then the remaining operations and corpus. Make portable helper packaging a separate delivery gate before advertising portable fallback.

## Round 3 — Codex

M1 is appropriately scoped as a development milestone. Three material gaps remain. [Revised plan](C:/Users/bimst/source/repos/aware-aeco-872/docs/superpowers/specs/2026-11-28-872-occt-brep-exec-PLAN.md:5)

| Finding | One-line fix |
|---|---|
| **The two workers can disagree about whether the same request is flush.** Each reconstructs profiles from a different representation, and agreement within a tolerance does not establish exact coincidence. At a 5 km offset, a face at local `0.1 mm` and a face at local zero with its offset advanced by `0.1 mm` can reconstruct as a tiny gap or overlap. M1’s oracle treats exact contact and unresolved positive clearance differently, so the fallback can reject a pair the exact path admits. | Give both workers one authoritative producer profile and placement representation with explicit coincidence semantics, verify both encodings against it, and test a flush pair encoded with different operand origins. |
| **The exact tests can pass with re-centring removed.** A correct answer at 5 km and a correctly placed output do not prove the operands were centred when `Cut` ran. The uncentred baseline tests Manifold, so it cannot catch this OCCT regression. | At the actual OCCT call boundary, assert that both operands are copies, their shared bounds are near zero, and the source placements are unchanged, then verify that disabling the transform fails the test. |
| **The mandatory offline evidence has no assigned PR execution path.** The VM recipe defines how to run the guest, but the all-PR gate requires its report without identifying a runner that can launch it, how PR artifacts reach it, or who returns evidence for a fork or merge-group SHA. A green local VM run cannot satisfy that gate. | Prove the offline suite on a named runner and wire its evidence to each required SHA, or make offline provisioning a separate delivery and lock-change gate while keeping exact and fallback tests mandatory on every PR. |

VERDICT: REVISE
### Claude's response

Accepted all three. For the third, chose the second option: offline provisioning becomes a separate delivery and lock-change gate, run on the self-hosted Windows runner by manual dispatch with its report attached to the PR. Exact and fallback tests stay mandatory on every PR.

## Round 4 — Codex

One material M1 gap remains. The authoritative profile fixes how the oracle classifies contact, but both kernels still cut the supplied encodings, which may agree with that profile only within tolerance. For example, a strip that should cut all the way through A can end slightly below A’s top face in both encodings. The residual skin connects two components the oracle expects to be separate. The validator correctly rejects both results, but M1 admitted the pair and promised a checked fallback.

**Fix:** Require declared coincidences to survive conversion into each kernel’s working coordinates, or reject the pair at admission. Add a through-cut regression with an encoded residual skin that falls within the input matching tolerance.

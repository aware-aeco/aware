# AWARE #872 geometry exec implementation plan

Implement **M1 only** in this slice. Each milestone has its own delivery gate. The November 25 ruling selects Open Cascade (OCCT) and adds both STEP operations to #872 acceptance. The background CLI runs out of process. Interactive geometry stays on the existing viewer path. [Issue #872](https://github.com/aware-aeco/aware/issues/872) · [November 25 owner ruling](https://github.com/aware-aeco/aware/issues/872#issuecomment-7153904321)

## M1 · Windows x64 difference and mesh fallback

### CLI and v1 contract

Add the standalone command in `cli/src/commands/geometry.rs` and put the contract, runtime and worker supervision under `cli/src/geometry/`. The CLI owns input validation, worker selection and the standard JSON envelope. Each invocation handles one request. Gate `geometry install` and `geometry exec` behind an opt-in development build feature and hide them from normal CLI help. Omit the feature from ordinary release builds and keep the command out of public usage instructions until M4 verifies fallback in supported install layouts.

```text
aware geometry install --occt --python <absolute-path-to-python.exe> [--wheelhouse <directory>] --json
aware geometry exec @request.json --json
aware geometry exec - --json
```

Read UTF-8 through EOF for stdin and enforce the same 32 MiB request cap for both inputs before parsing. All objects are closed and all listed fields are required. Decode `brep_b64` with a required-field representation that distinguishes omission from explicit `null`, including in child success replies. JSON numbers must be finite, indices must be nonnegative safe integers, and BRep bytes use standard padded base64. Cap each mesh at 100,000 triangles. The complete serialized CLI envelope, including wrapper, warnings and trailing newline, may occupy at most 32 MiB.

```text
Vec3 = [number, number, number]
Frame = { units: "mm", origin_mm: Vec3, axes: [Vec3, Vec3, Vec3] }
Mesh = { positions_mm: Vec3[], triangles: [uint, uint, uint][] }
Decimal = string  (signed base-10 decimal, up to 32 digits, no exponent)
Profile = { xy_mm: [Decimal, Decimal][], z_mm: [Decimal, Decimal] }
Operand = { offset_mm: Vec3, profile: Profile, brep_b64: string | null, mesh: Mesh }

Request = { schema: "aware.geometry.exec.request/v1",
            op: "boolean", kind: "difference", frame: Frame,
            chord_height_mm: number, a: Operand, b: Operand }

Cut = { offset_mm: Vec3, brep_b64: string | null, mesh: Mesh, volume_mm3: number }
Response = { schema: "aware.geometry.exec.response/v1",
             op: "boolean", kind: "difference", frame: Frame,
             status: "validated_brep" | "mesh_fallback" | "unavailable",
             exact_status: "validated" | "unavailable" | "failed",
             warnings: { code: WarningCode, message: string }[], result: Cut | null }

WarningCode = "occt_runtime_missing" | "occt_import_failed" | "occt_timeout"
            | "occt_worker_failed" | "brep_validation_failed" | "brep_input_missing"
            | "mesh_invalid" | "mesh_worker_failed" | "mesh_timeout"
            | "budget_exceeded" | "chord_height_unverified" | "coincidence_mismatch"
```

- The right-handed member basis is orthonormal within `1e-12`. Its vectors are the columns of `axes`. BRep and mesh vertices share the operand offset and member axes. Reconstruct a point as `origin_mm + axes * (offset_mm + local_point)`. Apply that mapping once. The workers operate in local millimetres. `chord_height_mm` is finite, positive and absolute. BRep uses the pinned OCCT BRepTools stream with stored triangulation omitted.
- The first admitted producer is the repo-owned M1 development fixture generator, `geometry-worker/fixtures/generate_difference.py`. It takes dimensioned convex XY polygons extruded over Z intervals, builds native prisms in OCP and builds their welded indexed meshes directly from the same polygon, height and placement. Generate both representations in the same local coordinate system before adding placement. The paired-representation guarantee comes from this producer and applies to the complete occupied solid, including winding and placement. Arbitrary independently supplied BRep and mesh pairs are outside M1 admission. Check the producer's paired outputs against the same input dimensions, and send its generated JSON through the real CLI. The no-runtime test generates the request in advance and runs it in a clean execution environment.
- M1 admits one straight Z extrusion of a convex XY polygon per operand. The producer emits `profile` from its input dimensions and placement before rounding either encoding. Its exact decimal coordinates are in the member frame and define the authoritative polygon and base/top Z levels for both workers. The exact worker verifies the BRep and mesh topology and checks each encoding with its operand offset against that profile within the declared positional tolerance. The mesh dispatcher verifies its mesh and offset against the same profile. `brep_b64: null` with an admitted nonempty mesh requests mesh execution with `brep_input_missing` when the exact runtime is otherwise available.
- Admit verified empty and unchanged cuts and nonempty cuts with closed, consistently oriented manifold boundaries. Admit connected solids with strictly enclosed cavities and disjoint solid components whose closures are separated. Sum signed shell volumes at the shared result offset, with outward exterior shells contributing positively and inward cavity shells negatively. Reject self-intersections, shells or components that touch, and pinches along an edge or at a vertex, including a cavity tangent to the exterior along a vertical line. Apply the same topology policy to BRep and mesh. Empty results use zero volume, null BRep, empty mesh arrays and an A-based anchor, with the quality status of the path that verified the cut. Nonempty exact results carry BRep and mesh. Nonempty mesh results carry null BRep. Reuse a result as an operand only after the producer verifies that it is one admitted prism and preserves its offset and frame.
- Under `--json`, successful cuts have exit zero and the response in the standard envelope's `data`. Malformed requests use the CLI error envelope and nonzero exit before either worker launches. For an admitted pair within budget and with an admitted result topology, a functioning staged helper must return a checked mesh difference after exact rejection or unavailability, including a verified empty result where applicable. Both required flush fallback cases must yield nonempty cuts. Pair `validated_brep` with `exact_status: "validated"` and `mesh_fallback` with `"failed"` or `"unavailable"`. Mesh fallback carries the exact-path warning and `chord_height_unverified`. Discard rejected geometry, bytes and metrics. Pending the owner's ruling, exhausted fallback returns a typed `unavailable` envelope with warnings, `result: null` and no geometric figures in the payload or warnings. Use exit zero provisionally for this development-only typed response. Final caller behavior and exit status require the owner's ruling before v1 is frozen.

### Coordinates and acceptance

1. Validate local coordinates before using placement. Compute conservative local bounds from the native shape and the mesh in double precision. Include native subshape tolerances, mesh quantization and outward rounding for placement arithmetic. Before dispatching any Boolean, compare the bounds using relative offsets in double precision. Strict separation along any axis beyond those margins proves disjointness. For difference, validate and return A at its own centred anchor with the quality of the path used. Near contact goes through the Boolean and acceptance rule.
2. For the Boolean path, take the midpoint of the union of the conservative bounds in A-relative space. Compute each translation as `(operand.offset_mm - a.offset_mm) - pair_midpoint_relative_to_a`; return `a.offset_mm + pair_midpoint_relative_to_a` as the output offset. The disjoint shortcut instead centres A from its own bounds. Keep the world origin out of all kernel calculations. Check both the original operand-local coordinates and the centred operand and pair bounds. Start with a maximum absolute coordinate of `2^14 mm` on each axis at each of those stages, and require the shortest profile edge and prism height of each operand to span at least eight float32 ULPs at the largest working coordinate. Use outward error bounds on the relative translations and verify that adding the output anchor preserves the producer's placement within the fixture's positional tolerance. Report `budget_exceeded` if the relevant path cannot preserve the required precision. A large offset is admissible when the original coordinates retain the detail and the independent pair either centres within budget or is provably disjoint.
3. Deep-copy both OCCT operands with `BRepBuilderAPI_Copy` before translating them or calling any Boolean. After admission passes, use non-destructive mode, parallel mode off and one `Cut` per non-disjoint request. Assert zero **requested extra** fuzz, the pinned kernel's effective native floor and zero retries. For OCCT 7.8.1, `SetFuzzyValue(0)` resolves to `Precision::Confusion()`. Read back the actual value in the pinned worker test and record the native kernel version with it. Check completion and error status. [OCCT 7.8.1 implementation](https://raw.githubusercontent.com/Open-Cascade-SAS/OCCT/V7_8_1/src/BOPAlgo/BOPAlgo_Options.cxx)
4. Build the expected occupied and removed cross-sections from the same authoritative profiles and sorted distinct base and top Z levels on both paths. Determine coincidence and contact with exact predicates on the decimal values, including exact comparisons of clipping intersections where needed. Before running either Boolean, verify that every coincidence established by those predicates holds exactly between the corresponding encoded features in that kernel's working coordinates. Inspect the located OCCT faces, edges and vertices after translation and the centred mesh vertices and triangles after float32 conversion, as supplied to Manifold. Treat their stored binary coordinates and geometric coefficients as exact values and check the mapped incidence, including equality of cap levels, collinearity, coplanarity and the coincident extent of the trimmed features where applicable. Require exact equality for the relations that define each coincidence. The input matching tolerance does not apply to these checks. Run the mesh check with the dispatcher's centring and conversion even when OCCT is available. With an exact operand pair and runtime, require both checks before either Boolean. Mesh-only execution requires the mesh check. Measure positive clearances from the same profiles and preserve them for the budget check. In each open slab, the occupied section is A's active polygon minus B's active polygon and the removed section is their active intersection. Use bounded double-precision constructions with certified error bounds for numeric measures. Integrate occupied areas over slab heights for expected volume, and derive expected bounds and boundary topology from the sections and their transitions at the Z levels. Prove unchanged by zero removal and empty by zero retained occupancy. Charge oracle and section-comparison work against the mesh budget and a fixed limit of four million visited edge pairs.
5. Before either Boolean, record conservative positional error budgets by axis for both paths. Add input representation error (including producer quantization and OCCT subshape tolerances on the exact path), outward-rounded placement and recentering error (including anchor reconstruction), predicate/construction error, and the pinned kernel's verified positional tolerance. Include the effective OCCT fuzzy floor on the exact path and centred float32 conversion and the pinned Manifold tolerance on the mesh path. Use the larger per-axis path budget for shared feature admission. Use lock-verified kernel bounds and the producer's declared tolerance cap so mesh-only execution can compute this threshold without OCCT. Verify that exact input tolerances fit the cap when OCCT is available. Require each positive Z thickness and XY clearance that defines a removed or retained feature to exceed eight times the corresponding budget. Measure clearance between distinct boundary features, including narrow layers, necks, strips and gaps created by clipping. Merge equivalent subdivisions, including adjacent levels with identical sections. Assess actual shared contacts under the topology rule. Use a certified lower bound for each clearance. An unresolved predicate or a positive feature at or below the threshold yields `budget_exceeded` and withholds geometry. Keep the input ULP and extent guards as separate checks.
6. Check each candidate's occupied cross-sections against the oracle across every slab. Verify that its boundary is piecewise prismatic, with horizontal caps at the expected Z levels and side faces parallel to Z within the declared error. Check all candidate transition levels against the expected levels and verify occupancy on both sides of each transition so extra intervals or sloping sides cannot hide between samples. At a representative Z in each slab, recover closed section loops from the BRep or indexed triangles, account for holes and disjoint components, and overlay the candidate and expected loop boundaries. Compare occupancy in every cell of that overlay outside the declared boundary allowance, using a certified interior sample per cell. Require corresponding boundary loops and transitions within the allowance, preserving incidence and nesting after equivalent subdivisions are merged. Withhold geometry on unresolved comparisons. Include interior removed and retained witnesses at certified clearance and retain those checks in the CLI fixtures. Apply the same test to the exact BRep, its final tessellation and the final fallback mesh, including empty and unchanged candidates.
7. For nonempty exact output require `BRepCheck_Analyzer::IsValid`, the admitted manifold shell topology, and finite positive net volume for each solid without stray faces, edges or vertices. Verify shell orientation and nesting, including negative signed contributions for cavity shells. Measure volume with `BRepGProp` on BRep surfaces with adaptive integration targeting `1e-12` relative. Check expected bounds within the positional allowance and require `0 <= result volume <= A volume` within the comparison band. Compare with the oracle volume within `max(1e-9 mm³, 1e-12 * scale)`, where scale is the larger magnitude compared. Analytic regression cases also assert `1e-12` relative error when that band reaches the absolute floor. Use the final signed mesh volume for fallback and compare against the oracle using a band declared before the Boolean that includes the input, placement and kernel errors and float32 rounding. Derive the volume allowance from a conservative boundary displacement bound including surface area and numeric integration error.
8. Tessellate each accepted exact component with `BRepMesh_IncrementalMesh` using the requested absolute chord height and fixed 0.25 rad angular deflection. Apply face locations and orientation in the centred frame and validate the final welded indexed mesh, including finite positions, valid indices, positive areas and signed shell orientation. Compare its bounds and signed volume with the accepted BRep, and check its occupied sections and the same removed and retained witnesses. Declare the tessellation displacement and volume allowances before meshing from the admitted planar geometry, numeric error and the seam weld tolerance. Withhold the exact result and enter fallback on any artifact mismatch. Publish the BRep volume for exact results only after the final mesh passes.

### Process supervision

Materialize the pinned exact worker script from the CLI build and launch the validated venv interpreter by absolute path with `-I`. For both workers reuse suspended launch and assignment to a kill-on-close Windows Job Object before resuming the child. Start a 30-second monotonic deadline at launch for stdin writes, exit waiting and pipe drains. Write bounded stdin asynchronously, close it on completion, and drain both pipes concurrently. Cap stdout at 32 MiB and stderr at 64 KiB. Native diagnostics use captured stderr or a bounded diagnostic file. Protocol stdout carries only the reply. [Existing process supervision](../../../cli/src/commands/model_reader_host.rs#L606)

On ordinary completion reap the direct child, close its process handle and require pipe EOF and zero active job processes within the deadline. On deadline or overflow cancel stdin, call `TerminateJobObject`, reap the direct child and join the pipe tasks within a bounded cleanup interval. For both cases poll `QueryInformationJobObject(JobObjectBasicAccountingInformation).ActiveProcesses` to zero within the applicable bound. Release process references held by the supervisor so accounting can drain. Windows documents Job Object handle signalling for the end-of-job time limit. Use process handles for child reap and accounting for tree drain. Give fallback its own 30-second budget after confirmed cleanup. If cleanup cannot be confirmed within the bound, close the kill-on-close job and return the bounded `unavailable` response with a worker-failure warning. [Microsoft Job Objects documentation](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) · [Job accounting](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information)

Accept child output only after clean completion and exit zero. Bound it before parsing and require exactly one JSON object of the expected closed reply shape with all required fields and valid status/result combinations. Malformed JSON, invalid reply shape or nonzero exit after a valid-looking reply from the exact worker triggers fallback with `occt_worker_failed`. Equivalent mesh worker failures exhaust fallback with `mesh_worker_failed`. Exact geometry rejection uses `brep_validation_failed` and enters fallback. A mesh topology rejection exhausts fallback with `mesh_invalid`. A precision rejection uses `budget_exceeded`. A lost or unverified declared coincidence rejects the pair at admission on either path. Return the standard success envelope with exit zero, `status: "unavailable"`, a `coincidence_mismatch` warning identifying the failed relation, and `result: null` without geometric figures. Use `exact_status: "failed"` when admission rejects an exact-enabled pair and preserve the existing exact status for a mesh-only request or a rejection during fallback. This admission failure is terminal. Serialize and measure the entire envelope before writing stdout. An oversized exact payload or envelope enters fallback. An oversized mesh reply or envelope exhausts it. Emit a bounded warning envelope on exhaustion.

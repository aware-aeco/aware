## 2. Slice A design

### 2.1 Provider, not constants

Introduce a small code-owned `Provider` (enum `Google | Microsoft`) on each `Operation`, carrying:

| | Google | Microsoft |
|---|---|---|
| token endpoint check | `config.token_url() == GOOGLE_TOKEN_URL` (unchanged) | `config.token_endpoint_is_own()` **and** origin is `https://login.microsoftonline.com` (tenant rewrite allowed, BYO `token_url` refused) |
| identity request | `GET openidconnect…/v1/userinfo` | `GET https://graph.microsoft.com/v1.0/me?$select=id,userPrincipalName` |
| stable id | `sub` | `id` (directory object id; for a personal account the MSA id) |
| presentation label | email iff `email_verified` | `userPrincipalName`, cleaned, label only (never part of the binding) |
| scope normalisation | as granted | strip a leading `https://graph.microsoft.com/`, case-insensitive compare (Microsoft returns short names; both forms appear in the wild) |
| sentences | today's | Microsoft equivalents ("No Microsoft account is connected in this slot.", …) |

The binding id formula is unchanged (`integration`, `slot`, stable id), so Google bindings keep their
values. `Endpoints::production(integration)` takes token/identity URLs from the provider; tests keep
pointing them at fixtures and must widen `allowed_origins` to do so.

Open question for review: should the Microsoft stable id be `tid:oid` rather than `oid`? `/me` does not
return the tenant id; getting it means decoding the access token (we do not parse JWTs) or an extra
`/organization` read (needs no extra scope but doubles identity cost, and fails for personal accounts).
Object ids are GUIDs, unique across tenants in practice; the slot already scopes the binding. Proposal:
`id` alone.

### 2.2 Operation table grows two things

- **Path inputs.** `InputMap.location: Query | Path`, `required: bool`. A path input is a required
  string, ≤ 256 bytes, restricted charset `[A-Za-z0-9!._-]` (Graph drive ids are `b!…` base64url-ish
  with `!`, item ids alphanumeric with `!`; `root` is a valid folder id), then percent-encoded per
  segment anyway. The URL is a template with `{drive-id}` / `{folder-id}` placeholders filled only from
  validated inputs; the origin check runs on the template's fixed origin, and the built URL is
  re-checked to sit on it. `inputs_json` reports the real `location` / `required`.
- **Per-operation fixed query.** Replace the single `fields` mask with `fixed_query: &[(&str, &str)]`
  (Google: `fields=…`; Graph: `$select=…`). Part of the operation digest, as today.
- **Projection is per operation** (`fn(&Json, limit) -> Option<Json>`), included in the digest by name +
  version string so a changed projection changes `operationSha256`.
- **Scopes per operation**: `accepted_scopes` (any one suffices) and `request_scope` (the one AWARE names
  in the reconnect hint), plus `admin_consent: bool`. Google's row keeps `OPTIONAL_GOOGLE_SCOPES` (the
  single list `gmail.send` shares).

### 2.3 `microsoft-365` `list-folder`

- `GET https://graph.microsoft.com/v1.0/drives/{drive-id}/items/{folder-id}/children`; the literal
  `drive-id: me` selects the code-owned alternate path `/me/drive/items/{folder-id}/children` (the
  person's own OneDrive without knowing its id — FloLess's first listing, and the E2E's).
- fixed query: `$select=id,name,size,folder,file,lastModifiedDateTime,parentReference`; input `page-size` → `$top`
  (1..200, default 100).
- **One page, no `@odata.nextLink` following.** The result says `more-available: true` when Graph sent a
  next link. A continuation cursor is deferred to the Phase 2 v2 contract's opaque continuation tokens —
  following a server-supplied absolute URL is exactly what the code-owned rule forbids, and FloLess's
  tool has no cursor input today. (The command doc's "follows nextLink" sentence is corrected.)
- Projection: `items: [{id, drive-id, name, size?, is-folder, mime-type?, modified-time?}]` (`drive-id`
  from `parentReference.driveId`, so a caller can open a child folder; `parentReference` is added to
  `$select`), `more-available`;
  ids/names cleaned and length-capped like the Google projection; at most `page-size` entries.
- Scopes accepted: `Files.Read`, `Files.Read.All`, `Files.ReadWrite`, `Files.ReadWrite.All`. Request
  scope: `Files.Read.All` (lets a person list a shared or SharePoint drive they can already see;
  `Files.Read` covers only their own drive). **No admin consent** (delegated `Files.Read.All` is
  user-consentable). Decision for Pawel: `Files.Read.All` vs `Files.Read` as the scope FloLess Desktop
  adds — see §5.
- Origins: `call_origins_for("microsoft-365") = ["https://graph.microsoft.com"]` (identity and data
  share it).

### 2.4 Manifest `microsoft-365` 0.3.0

- `auth: {scheme: oauth2, secret: microsoft-365}` (required by `manifest_slot`).
- Remove `transport.cli` (it named a binary that never existed); `transport.rest.base` stays, so
  dispatch is `rest`. Agent `status` becomes `available`; **every command except `list-folder` gets
  `status: planned`**, so nothing else becomes "runnable" through the generic REST renderer by accident.
  Test: every non-reviewed command in the shipped manifest is planned.
- `list-folder`: `mode: read`, `method: GET`, absolute `path`, `page-size` input, output schema = the
  projection.
- **Per-command permissions** (task item 3), a new optional generic manifest field:
  ```yaml
  permissions:
    scopes: [Files.Read.All]     # what to request; any accepted scope listed in AWARE's code also works
    admin-consent: false
  ```
  Typed in `manifest/agent.rs` (`Option<Permissions>`), documented in `10-core/agent-spec` and shown in
  `aware agent describe`. Declared on **every** command (planned ones too), so a caller can explain
  consent before sign-in for the whole surface (e.g. `teams.channel.post-message` →
  `ChannelMessage.Send`, admin consent true). A test asserts that for each reviewed operation the
  manifest's `permissions` equal the code's `request_scope` / `admin_consent` — the code stays the

- `call-capabilities` adds `permissions: {scopes, adminConsent}` (from code) to its v1 output —

- Registry: version bump, `registry-catalog.json` via `aware agent reindex`; `python

### 3.1 Slice B1 addendum (2026-11-02, before code)

Status: **Codex APPROVE, round 3** (round 1 REVISE 10 findings, round 2 REVISE 3; logs in the PR).
Implementation note: OData annotation keys (`@odata.etag`, …) in a list item's `fields` are not columns,

**Rev 2 — Codex round 1 (REVISE, 10 findings; these supersede the text below where they differ):**

- **B1-1 (`$top` on SharePoint).** Graph documents only `$filter`/`$expand` for list items and does not
  establish `$top` for lists. Both SharePoint commands bound **locally** (`Location::Local`
  `page-size`), send no `$top`, and rely on R1-8 truncation reporting plus the existing response-byte cap
  (an oversized page is `E_CALL_OUTPUT_TOO_LARGE`, never a silent cut). Wire tests assert no `$top`.
- **B1-2 (mail search is not raw KQL).** `outlook.mail.search` takes **typed inputs** rendered by code,
  no caller-written KQL: `text` — 1..16 words, each 1..64 chars of letters, digits, `.`, `_`, `-`, `@`
  (no `:`, no wildcard `*`, no parentheses), none equal (case-insensitive) to `AND`, `OR`, `NOT`, `NEAR`,
  `ONEAR`; and `from` — one address (`local@domain`, local `[A-Za-z0-9._%+-]{1,64}`, domain DNS labels as
  for `site-id`), rendered `from:<address>`. At least one is required. The `$search` value is `"` + the
  space-joined terms + `"` (KQL implicit AND); query pairs are percent-encoded by the URL builder, so
  `&`, `#`, `%`, `=` and non-ASCII cannot form extra parameters — wire tests send each and assert the
  decoded `$search` and that there is exactly one `$search` pair. Refusal tests for `:`, `*`, `(`,
  `OR`, quotes, 17 words. Date restriction is left out of B1 (the KQL date form needs live proof first).
  The manifest's raw-KQL description and `top` input are replaced.
  *Round 2:* a word may not **begin** with `-` (KQL's `-term` is NOT; inner hyphens stay), refused
  with zero requests (`-draft`, `budget -draft`). Characters the grammars refuse (`&`, `#`, `=`, `:`)
  get zero-request refusal tests; percent-encoding is tested with accepted values (`%` and `+` in an
  address local part, non-ASCII letters in a word), and the URL builder's arbitrary-character behaviour
  stays its own unit test.

was returned. Required `since` keeps a caller from silently reading "all history" when it meant
"recent". If live shows the channel list is *not* newest-first, the command is cut from this slice

#### 4.1 Rev 2 — Codex R1 fixes (supersede the text above where they differ)

- **C-1 Thread activity, not root time.** For `teams.channel.list-messages`, a thread's activity is the
  latest of the root's `createdDateTime`/`lastModifiedDateTime` and every *received* reply's
  `createdDateTime`/`lastModifiedDateTime`. The thread is kept when that activity is strictly `>`
  `since`. It is filtered (and counted in `filtered-before-since`) only when the activity is *known*
  older: if the root carries `replies@odata.nextLink` (unseen replies) or any timestamp in the thread is
  missing or unparsable, the thread is **kept** with `activity-unknown: true`, never declared old.
  Filtering happens on the full received page, before the local page cut; a kept reply is never dropped
  because of `since` (the thread is the unit). Tests: an old root with a new reply is kept; an old root
  whose only new reply sits beyond the 50-reply cap is still kept (activity uses every received reply,
  not only the kept ones); an old root with `replies@odata.nextLink` and no newer received reply is kept
  with `activity-unknown`; an old thread with no continuation is filtered and counted.
- **C-2 Reply completeness.** Graph's `$expand=replies` returns up to 200 replies and signals more with
  `replies@odata.nextLink`. Each root gets `replies-more-available` (true on that nested link or on the
  local 50 cut) and `replies-omitted` counts only received replies AWARE discarded — never an estimate
  of unseen ones. The nested link is never returned or followed. Test: nested link, no top-level link,
  fewer than 50 replies → `replies-more-available: true`, `replies-omitted: 0`, top-level
  `more-available: false`.
- **C-3 HTML → text algorithm.** Walk the parsed fragment's node tree depth-first. Skip the whole
  subtree of `script`, `style`, `template`, `noscript`, `head`, `title`. Text nodes contribute their
  (parser-decoded, so decoded exactly once) text with every run of whitespace collapsed to one space.
  `br` emits `\n`; `p`, `div`, `li`, `tr`, `h1`–`h6`, `blockquote`, `pre` emit `\n` before and after.
  Afterwards: collapse runs of `\n` (with surrounding spaces) to one `\n`, trim, remove control
  characters other than `\n` and `\t`, then cap at 4096 chars (cut named in `truncated`). `<at>`
  mention text is ordinary text. `text` is plain text: a decoded `&lt;b&gt;` stays the literal `<b>` and
  consumers must render it as text, never as HTML (stated in the command docs). Tests: script/style/
  template contents absent; encoded literal markup kept literal; mention text kept; block boundaries
  give single newlines; a control character removed; the cap.
- **C-4 `since` reaches the projection.** `Wire` gains a typed `since: Option<DateTime<Utc>>` (set only
  by a validated `graph-utc-timestamp/1` input, whichever its location) and `Projection::apply` takes a
  `ProjectionContext { limit, since }` passed through the read path; earlier projections ignore
  `since`. The input's `format` and its `location` (`filter` for chat, `local` for channel) are in the
  operation's canonical inputs, so they are digest-bound. Transport test: the same fixture page read
  with two `since` values returns different messages.
- **C-5 Attachment URLs by allowlist.** A `contentUrl` is kept only if it parses as an absolute URL
  with scheme `https`, no userinfo, no explicit port, and a host that — lowercased — is
  `<tenant>.sharepoint.com` or `<tenant>-my.sharepoint.com` (one DNS label before `.sharepoint.com`),
  and its percent-decoded path contains no `hostedContents` segment (case-insensitive). Anything else is
  withheld: the attachment stays with `url-withheld: true`. `graph.microsoft.com` is never allowed, so
  a hosted-content URL cannot pass however it is encoded. AWARE never fetches an attachment. Tests:
  encoded `hostedContents`, upper-case host, userinfo, `evil.com/x.sharepoint.com`,
  `x.sharepoint.com.evil.com`, a port, `http:`; each sentinel absent from output, errors and the log.
- **C-6 System messages need a header.** Both message reads send the code-owned header
  `Prefer: include-unknown-enum-members` (Microsoft documents it as required to receive

#### 4.1 Rev 3 — Codex R2 fixes (supersede Rev 2 where they differ)

- **C-9 (C-5 completed) No query, no fragment.** An attachment `contentUrl` is kept only if, in addition

  `download.aspx?…` or any other parameter is withheld (`url-withheld: true`), never stripped and

- **C-12 A controlled live gate.** The seeds go into a **new channel created for the test** (no other

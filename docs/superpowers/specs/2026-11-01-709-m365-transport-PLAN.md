1. **Path ids (R1-1, R1-9).** A Graph opaque id input is validated as `[A-Za-z0-9!_-]{1,256}` — **no
   dot at all**, so `.`/`..` cannot form; empty refused. Validation is per input (`IdKind::GraphDriveId`,
   `GraphItemId`), not one charset for every future operation; B and C define their own kinds (Teams
   ids with `:`/`@`, SharePoint composite site ids with `,`, worksheet names) with their own encoders and
   real-format fixtures. The URL is assembled segment by segment (`url::Url::path_segments_mut().push`,
   which percent-encodes) from a fixed list of literal segments + validated inputs — never by string
   templating — and the result's path is asserted to have exactly the expected segment count. The
   `drive-id: me` route is a second fixed segment list. Zero-network tests for every refused form on
   both routes.
2. **Google digest stays byte-identical (R1-2).** The Google row keeps today's canonical representation
   exactly (`"fields": LIST_FILES_FIELDS`, `"identity": GOOGLE_USERINFO_URL`, `"scopes"`, no projection
   field). A test pins the pre-refactor canonical **string and digest** as literals, captured from
   `main` before any edit. Microsoft rows use a new canonical form (`OPERATION_SCHEMA` unchanged; extra
   keys `provider`, `routes` (both segment lists), `pathRules` (id kind per input), `query` (fixed
   pairs), `projection` (name + version), `identityScopes`, `scopes`, `adminConsent`). Canonical form is
   chosen by provider, so a future change to the Google row changes its digest as it should.
3. **Identity prerequisite (R1-3).** Each provider declares `identity_scopes` that must **all** be granted
   in addition to the operation's "any one of" scopes: Microsoft `User.Read`, Google none (userinfo needs
   `openid`/`email`, already in the default consent). Missing either → `scope-missing`; the hint names
   every missing scope (`--scopes User.Read,Files.Read.All`). Test: `Files.Read.All` without `User.Read`.
4. **Scope equivalence through refresh (R1-4).** `refresh.rs` compares granted scopes to decide whether a
   refresh keeps the credential generation. For `microsoft-365` only, scopes are compared after
   Microsoft normalisation: strip exactly the prefix `https://graph.microsoft.com/` (no other host,
   lookalikes kept as-is), ASCII-lowercase; Google keeps today's case-sensitive comparison. Tests:
   `Files.Read.All` → `https://graph.microsoft.com/Files.Read.All` keeps the generation;
   `https://graph.microsoft.com.evil/Files.Read.All` does not equal it; dropping a scope rotates it.
5. **Permission metadata facts (R1-5).** `admin-consent` means *the provider's documented delegated
   permission requires admin consent* (Microsoft's permissions reference "Admin consent required"
   column), not tenant policy, which can demand it for anything; the spec says so, and that manifest
   `permissions` never authorizes anything (code decides). Every command's entry is audited against the
   permissions reference in the PR (corrections: delegated `ChannelMessage.Send` and `Chat.ReadWrite` do
   **not** require admin consent; `ChannelMessage.Read.All` and `Sites.ReadWrite.All`-class do — checked
   per row). The stale `config.rs` comment is corrected. Typed field: unknown keys / wrong types are a
   validation error in `aware agent validate`; omitted means "not declared".
6. **Runtime gate (R1-6).** The manifest declares `status: requires-runtime` +
   `minimum-cli-version: 0.166.0` (the release that will ship this code), so an older CLI refuses it
   with `E_AGENT_RUNTIME_TOO_OLD` instead of rendering `list-folder` through the generic REST path. The
   registry is not touched in this PR. Tests: older runtime → refused; current → the reviewed handler
   runs; a planned command is refused through `agent invoke` and through a workflow node.
7. **Workflow replacement check (R1-7).** `run_for_workflow_with` gains the `check_not_replaced` step
   before the data request (it has none today — a gap for Google too, fixed for both). Test: slot
   replaced after token resolution → `E_CREDENTIAL_CHANGED replaced`, zero data requests.
8. **No false "complete" (R1-8).** If Graph returns more entries than `page-size`, or any entry is
   dropped as malformed, the result says so: `more-available` is true on `@odata.nextLink` **or**
   truncation, and `omitted: <n>` counts dropped malformed entries. Ids are kept byte for byte when
   valid and the entry dropped (counted) when not — never "cleaned" into a different key. Names are
   display text and may be cleaned of control characters.
9. **Behavioural boundary tests (R1-13).** Microsoft fixtures through all three paths
   (capabilities, call, workflow); an attacker-sink fixture that must receive zero requests for:
   identity/data 3xx redirects, a BYO profile `token_url`, a profile rewritten between validation and

   the token URL to be exactly `https://login.microsoftonline.com/<tenant>/oauth2/v2.0/token` with

10. **Identity (R1-14).** Stable id = Graph `/me` `id`, exact and opaque: non-empty, ≤ 255 bytes, no

## 2. Slice A design

### 2.1 Provider, not constants

Introduce a small code-owned `Provider` (enum `Google | Microsoft`) on each `Operation`, carrying:

| | Google | Microsoft |
|---|---|---|
| token endpoint check | `config.token_url() == GOOGLE_TOKEN_URL` (unchanged) | `config.token_endpoint_is_own()` **and** origin is `https://login.microsoftonline.com` (tenant rewrite allowed, BYO `token_url` refused) |
| identity request | `GET openidconnect…/v1/userinfo` | `GET https://graph.microsoft.com/v1.0/me?$select=id,userPrincipalName` |
| stable id | `sub` | `id` (directory object id; for a personal account the MSA id) |
| presentation label | email iff `email_verified` | `userPrincipalName`, cleaned, label only (never part of the binding) |
| scope normalisation | as granted | strip a leading `https://graph.microsoft.com/`, case-insensitive compare (Microsoft returns short names; both forms appear in the wild) |
| sentences | today's | Microsoft equivalents ("No Microsoft account is connected in this slot.", …) |

The binding id formula is unchanged (`integration`, `slot`, stable id), so Google bindings keep their
values. `Endpoints::production(integration)` takes token/identity URLs from the provider; tests keep
pointing them at fixtures and must widen `allowed_origins` to do so.

Open question for review: should the Microsoft stable id be `tid:oid` rather than `oid`? `/me` does not
return the tenant id; getting it means decoding the access token (we do not parse JWTs) or an extra
`/organization` read (needs no extra scope but doubles identity cost, and fails for personal accounts).
Object ids are GUIDs, unique across tenants in practice; the slot already scopes the binding. Proposal:
`id` alone.

### 2.2 Operation table grows two things

- **Path inputs.** `InputMap.location: Query | Path`, `required: bool`. A path input is a required
  string, ≤ 256 bytes, restricted charset `[A-Za-z0-9!._-]` (Graph drive ids are `b!…` base64url-ish
  with `!`, item ids alphanumeric with `!`; `root` is a valid folder id), then percent-encoded per
  segment anyway. The URL is a template with `{drive-id}` / `{folder-id}` placeholders filled only from
  validated inputs; the origin check runs on the template's fixed origin, and the built URL is
  re-checked to sit on it. `inputs_json` reports the real `location` / `required`.
- **Per-operation fixed query.** Replace the single `fields` mask with `fixed_query: &[(&str, &str)]`
  (Google: `fields=…`; Graph: `$select=…`). Part of the operation digest, as today.
- **Projection is per operation** (`fn(&Json, limit) -> Option<Json>`), included in the digest by name +
  version string so a changed projection changes `operationSha256`.
- **Scopes per operation**: `accepted_scopes` (any one suffices) and `request_scope` (the one AWARE names
  in the reconnect hint), plus `admin_consent: bool`. Google's row keeps `OPTIONAL_GOOGLE_SCOPES` (the
  single list `gmail.send` shares).

### 2.3 `microsoft-365` `list-folder`

- `GET https://graph.microsoft.com/v1.0/drives/{drive-id}/items/{folder-id}/children`; the literal
  `drive-id: me` selects the code-owned alternate path `/me/drive/items/{folder-id}/children` (the
  person's own OneDrive without knowing its id — FloLess's first listing, and the E2E's).
- fixed query: `$select=id,name,size,folder,file,lastModifiedDateTime,parentReference`; input `page-size` → `$top`
  (1..200, default 100).
- **One page, no `@odata.nextLink` following.** The result says `more-available: true` when Graph sent a
  next link. A continuation cursor is deferred to the Phase 2 v2 contract's opaque continuation tokens —
  following a server-supplied absolute URL is exactly what the code-owned rule forbids, and FloLess's
  tool has no cursor input today. (The command doc's "follows nextLink" sentence is corrected.)
- Projection: `items: [{id, drive-id, name, size?, is-folder, mime-type?, modified-time?}]` (`drive-id`
  from `parentReference.driveId`, so a caller can open a child folder; `parentReference` is added to
  `$select`), `more-available`;
  ids/names cleaned and length-capped like the Google projection; at most `page-size` entries.
- Scopes accepted: `Files.Read`, `Files.Read.All`, `Files.ReadWrite`, `Files.ReadWrite.All`. Request
  scope: `Files.Read.All` (lets a person list a shared or SharePoint drive they can already see;
  `Files.Read` covers only their own drive). **No admin consent** (delegated `Files.Read.All` is
  user-consentable). Decision for Pawel: `Files.Read.All` vs `Files.Read` as the scope FloLess Desktop
  adds — see §5.
- Origins: `call_origins_for("microsoft-365") = ["https://graph.microsoft.com"]` (identity and data
  share it).

### 2.4 Manifest `microsoft-365` 0.3.0

- `auth: {scheme: oauth2, secret: microsoft-365}` (required by `manifest_slot`).
- Remove `transport.cli` (it named a binary that never existed); `transport.rest.base` stays, so
  dispatch is `rest`. Agent `status` becomes `available`; **every command except `list-folder` gets
  `status: planned`**, so nothing else becomes "runnable" through the generic REST renderer by accident.
  Test: every non-reviewed command in the shipped manifest is planned.
- `list-folder`: `mode: read`, `method: GET`, absolute `path`, `page-size` input, output schema = the
  projection.
- **Per-command permissions** (task item 3), a new optional generic manifest field:
  ```yaml
  permissions:
    scopes: [Files.Read.All]     # what to request; any accepted scope listed in AWARE's code also works
    admin-consent: false
  ```
  Typed in `manifest/agent.rs` (`Option<Permissions>`), documented in `10-core/agent-spec` and shown in
  `aware agent describe`. Declared on **every** command (planned ones too), so a caller can explain
  consent before sign-in for the whole surface (e.g. `teams.channel.post-message` →
  `ChannelMessage.Send`, admin consent true). A test asserts that for each reviewed operation the
  manifest's `permissions` equal the code's `request_scope` / `admin_consent` — the code stays the
  authority for what is accepted; the manifest is the published description.
- `call-capabilities` adds `permissions: {scopes, adminConsent}` (from code) to its v1 output —
  additive; FloLess ignores unknown fields today, and will read it to name the scope before sign-in.
- Registry: version bump, `registry-catalog.json` via `aware agent reindex`; `python
  scripts/sync_stats.py --write`; any agent-count assertions. Registry publication / `minimum-cli-version`
  follows the #664 pattern (lands after the release that ships the code) — confirm with Pawel.

### 2.5 What does not change

Request schema `aware.agent-call/v1`, record/result schemas, binding formula, generation checks
(before refresh, after refresh, immediately before dispatch), bounded no-redirect GET, body cap, deadline
budget, code-only log line, workflow path semantics (baked alias honoured, no identity step).

### 2.6 Tests (mirroring the Google ones, fixture servers)

- Microsoft happy path: capabilities `verified` with `stable_id = id`; call returns projected items.
- Token endpoint: tenant-rewritten endpoint accepted; BYO profile `token_url` → `E_CREDENTIAL_EXPIRED
  token-endpoint` before any refresh.
- Scope: `User.Read` only → `scope-missing` with the Microsoft hint naming `Files.Read.All`; both short
  and URL-form scopes accepted; `Sites.Read.All` alone refused.
- Path inputs: missing → `E_CALL_INPUT_INVALID`; `../x`, `a/b`, `%2F`, space, 257 bytes refused before
  any network; `root` accepted; the fixture asserts the exact path it received.
- Origin pin: production endpoints for microsoft-365 contain only graph + login hosts; a nextLink to

- Projection: folder vs file, missing size, extra fields dropped, > page-size entries truncated,
  `@odata.nextLink` → `more-available`.
- Operation digest changes when the projection version / fixed query / scopes change; Google

- Shipped manifest: only `list-folder` runnable; every command has `permissions`; reviewed op ⇔ manifest

### 2.7 Real E2E (gate)

Temp `AWARE_HOME`, install `microsoft-365` from the worktree, `aware connect microsoft-365` (device code;

## 4. Slice C outline (addendum before code)

- `teams.team.list` → `/me/joinedTeams` (`Team.ReadBasic.All`, user consent).
- `teams.channel.list` → `/teams/{team-id}/channels` (`Channel.ReadBasic.All`, user consent).

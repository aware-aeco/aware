# Plan — aware-aeco/aware#627 (atomic installs + run leases) and #629 (reference table + `aware agent gc`)

_Round 0, 2026-10-05, against aware `main` v0.150.0. Owner rule (pawellisowski/floless.app#1985): "Keep versions while referenced, not forever … AWARE owns the reference table." GC is the first AWARE code that deletes a store package, so leases and locks come first._

## 0. Facts that shape the design

1. Runs execute only verified, immutable store bytes (#626): `resolve_agents` → `assess_agent` re-hashes every candidate (`verify_package`); the run reads only `ResolvedCatalogue`; nested backing apps resolved once (`resolve_backing`); for-each / retries share the catalogue. Nothing re-resolves mid-run.
2. A run needs a package to keep **existing**; its bytes cannot change under it. Worst GC bug = a package disappears → refusal / failed run, never other bytes (every reader verifies; publish only after verify). **Determinism never depends on the reference table being complete — only availability does.**
3. Lock precedents: fs2 OS locks that die with the process (`pidfile::ExclusiveControl`; `artifact_retention` writer holds a shared lock on its lease file, pruner `try_lock_exclusive`; `pidfile::lock_is_contended` handles Windows error 33); `provider_store::prune` two-pass, fail-closed.
4. Rust opens files non-inheritable → bridges/sidecars spawned by a run don't hold its locks; a lease dies with the `aware` process.
5. `discover_agents_in` doesn't skip dot-dirs → anything staged under `agents/` must be two levels down.
6. FloLess keeps workflows under `AWARE_HOME/apps/<id>/`; `aware app run` only runs installed ids.
7. #628 PR3a (approval chain, `.aware-approvals/<hex>.lock`, `promoted-at`) is not merged yet; the GC reference scan depends on its schema.

## 1. #627 atomic installs — done vs remaining

Done by #626/#628-PR1 (don't redo): staged + digest-checked + receipted + snapshotted install before one rename; crash-safe `agent_store::snapshot`; update snapshots staged + every outgoing dir before removal; atomic lock writes; runs dispatch from the store.

Remaining:
- **R1** update swap = `remove_dir_all(prev)`, `remove_dir_all(final)`, `rename(staging, final)` (`registry.rs:531-539`): a crash/error between leaves no current copy; on Windows `remove_dir_all` can stop half-way and leave a **partial** `agents/<id>` which a legacy version-only lock (`legacy_version_only`) would snapshot and run — a real (narrow) determinism hole.
- **R2** fixed staging names under `cache/` (`install-staging/<id>`, `update-staging/<new_name>`) removed first → concurrent installs of one id delete each other's staging; `cache/` as a junction on another volume → EXDEV after the old copy is gone.
- **R3** `uninstall_agent` / `uninstall_app` synthesized agent delete in place → partial copy visible.
- **R4** no exclusion between installers and readers of the current copy (run preflight hashing/snapshotting, compile) → raw IO errors.

Fix — new `cli/src/install/swap.rs`, one transaction for all four writers:
- Per-agent swap lock `agents/.aware-swap/locks/<id>.lock` (fs2). Writers (install, update, uninstall, synthesized-agent writes in uninstall_app/rename) take it **exclusive** for every id they touch, sorted. Readers of the current copy take it **shared** while hashing/snapshotting `agents/<id>` (`assess_agent` Mode::Run, compile's snapshot).
- Txn dir `agents/.aware-swap/<txn-uuid>/` (same volume, two levels deep): `intent.json` {ids, new_name, incoming-digest, outgoing:[{id, digest?}]} fsynced, `incoming/` (replaces cache staging), `outgoing-<id>/`. Order: stage+verify incoming, receipt, snapshot → snapshot outgoing → rename each `agents/<id>` → `outgoing-<id>` (no-replace) → rename incoming → `agents/<new_name>` → delete txn. Step-4 failure renames outgoing back. No-replace `MoveFileExW(WRITE_THROUGH)` (factor `agent_store::publish_dir` into `crate::fs`).
- Recovery under the swap lock at the start of every install/update/uninstall of that id and in `aware doctor`: if the intent's final dir exists and hashes to incoming-digest → finish; else restore missing `outgoing-<id>` and drop incoming.
- A reader holding the swap lock shared sees complete-old or complete-new, never absence; if the resolver finds `agents/<id>` missing and the swap lock is contended it waits (blocking shared) and retries once.
- `agents/<id>` stays a directory (no "current pointer": ~40 call sites + FloLess reads `agents/` directly); unlocked readers may see a microsecond gap — documented.

## 2. Store reference lock + run leases (#627)

**Store reference lock** `AWARE_HOME/agent-store-control/store.lock`:
- **Shared** by every operation creating/relying on a store reference in flight: `agent_store::snapshot` (signature becomes `snapshot(paths, root, &RefGuard)` so the compiler finds every caller), install/update/uninstall, `app compile`, `app migrate prepare|plan|promote|revert`, app install/rename writing a lock, `app run` preflight from resolution until its lease is written.
- **Exclusive** only by `gc --apply`, via a bounded try-lock loop (`--wait`, default 30s → `deferred: store-busy`).
- Lock order: writers swap→store; runs/compile store→swap (shared, sorted). No deadlock: the only exclusive store requester (GC) never blocks and holds no swap lock.
- `cli/src/agent_store/guard.rs`: `RefGuard::shared(paths)` (blocking), `RefGuard::exclusive_within(paths, wait)`.

**Run lease** `cli/src/agent_store/lease.rs`, file `agent-store-control/leases/<run-id>.lease`:
- JSON `{format:"aware.agent-lease/v1", run-id, app, instance, pid, started-at, cli-version, packages:[{agent, version, digest, receipt-key, root, via?}]}` covering every `ResolvedCatalogue::agents()` root incl. synthesized `exposes-as-agent` packages and every nested app's agents; the FINAL catalogue when resolution runs twice (`Selection::Verified`).
- Acquire = `create_new` + write + `sync_all` + `try_lock_shared`, all while holding the store lock shared → GC never sees an unlocked fresh lease or an unleased resolved package.
- OS lock, not pidfile+heartbeat: dies with the process (kill, crash, power loss), immune to PID reuse, no expiry clock. Windows: shared LockFileEx keeps the JSON readable; release can lag briefly after a kill (conservative); dead lease files deletable (FILE_SHARE_DELETE).
- Wiring in `commands/app.rs::run`: wrap `resolve_run_agents` in `RefGuard::shared`; immediately after, `let _run_lease = RunLease::acquire(..)?; drop(guard);` — before validation preflights; `_run_lease` bound at function scope through both the long-running branch and the one-shot branch (incl. model-reader cleanup). `--simulate`: no lease. `--dry-run`: lease.
- Liveness: `try_lock_exclusive` on each lease file (contended = live; success = stale → unlock; deleted only by GC under exclusive store lock).
- **Last-needed stamps** for the recovery window: `agent-store-control/refs/<id>/<tree-hex>.last-needed` (latest RFC3339, `replace_atomically`, monotonic). Writers: lease acquire + drop, the swap txn (outgoing current digest), `write_lockfile` replacing an existing lock (outgoing lock's digests — one choke point), `uninstall_app`, `migrate discard`. A failed stamp only warns (window falls back to `snapshotted-at` — availability only). Guard test lists the stamp call sites (source scan + negative control).

`aware agent leases --json` → `{leases:[{run-id, app, instance, pid, started-at, live:true, packages}], stale:[{run-id, path}]}` (read-only).
`aware agent uninstall X` during a run: run unaffected (store), uninstall succeeds, output adds "N active runs still use X; their stored copies stay until they finish."

## 3. Reference table (#629) — `aware agent refs --json` (read-only, `agent_store/refs.rs`)

Discovery roots (honest): `AWARE_HOME/apps/*/` always; registered roots in `agent-store-control/roots.yaml` via `aware agent refs roots add|remove|list <dir> [--label floless]`, scanned like `apps/`. Locks AWARE can't see are documented as unprotected (they get `pin-not-installed` after GC, never other bytes).

| kind | what | kept while |
|---|---|---|
| current | each `agents/<id>` working copy (tree digest + receipt key, read under shared swap lock); an unhashable copy keeps EVERY package of that id (`current-unhashable`) | always |
| approved-lock | `<source-dir>/<app>.lock`: `agent-digests`, else `agent-bundle-pins` (version-only pins reference nothing in the store) | lock exists |
| candidate-lock | `.aware-migration/<app>.candidate.lock` base + target pins | file exists |
| approval-archive / successor-from | `.aware-approvals/<hex>.lock`, `approval.original`, each `successors[].from`; anchor = `promoted-at` of the successor that replaced it (matched by `from-lock-digest`), else archive mtime | anchor + window; while `HOLD.<app>` exists: forever |
| lease | live lease files | live |
| recent | `max(snapshotted-at, last-needed)` | that + window |

Fail closed → `complete:false` (and `gc --apply` removes nothing, `E_AGENT_GC_REFS_INCOMPLETE` listing blockers; no override in v1): unparseable lock/candidate/archive or unknown `approval.format`, unreadable app dir, missing/unreadable registered root, unreadable store package dir.

Output `aware.agent-refs/v1`: `{generated-at, recovery-window, complete, roots[{path, kind, status, apps}], blockers[], packages[{agent, version, digest, receipt-key, path, bytes, snapshotted-at, last-needed-at, state: kept|in-window|removable, kept-until, references[{kind, …}]}], invalid-packages[{path, reason, references}], leftovers[{path, kind: temp|trash}], stale-leases[]}`. A package failing `verify_package` is listed under invalid-packages: referenced → kept as evidence; unreferenced → removable under the same window ("repair is GC's job", promised in #626).

## 4. `aware agent gc [--apply] [--recovery-window <dur>] [--agent <id>] [--only <id>@sha256:…] [--wait <dur>] --json` (`agent_store/gc.rs`)

- Dry-run default (store lock shared; never blocks runs) → table + `would-remove`; `--apply` computes the same classification over the same state.
- Window: `--recovery-window` overrides `config.yaml` `agent-store.recovery-window`; default **30d**; `0s` allowed (tests/E2E); `<n>{s,m,h,d}`; malformed → error.
- `--only` refuses `E_AGENT_GC_REFERENCED` + references when anything keeps it (the #627 "removal is refused" acceptance).
- Apply: (1) `RefGuard::exclusive_within(wait)` else `ok:true, applied:false, deferred:"store-busy"`; (2) under it, any `.tmp-*` / `.trash-*` is from a dead process (all writers hold shared) — removable; `agents/.aware-swap` txns are swap recovery's, not GC's; (3) build the table under the exclusive lock; incomplete → stop; (4) per removable package, sorted: same-dir no-replace rename `<id>/<hex>/<key>` → `<id>/<hex>/.trash-<uuid>` (+ dir fsync) — atomic vanish under its real name; Windows open handle → `skipped:{reason:in-use}`, continue; write tombstone `<id>/<hex>/.removed-<key>.yaml` {agent, version, digest, receipt-key, removed-at, removed-by, cli-version}; delete stale lease files; (5) release, then `remove_dir_all` each `.trash-*` (failures → `pending-delete`, retried next GC).
- Never deleted: `agents/*`, `apps/*`, any lock/candidate/archive/HOLD/evidence, bridges, `agent-store-control/` (except stale leases), referenced or in-window packages, unrecognized names under `agent-store/` (reported), anything when the table is incomplete.
- A GC'd pin later: `assess_agent` → `PinNotInstalled` / `E_APP_LOCK_AGENT_PIN_MISMATCH` (code kept for compatibility); with a matching tombstone the detail says "the approved version of tekla (0.1.5, sha256:…) was removed by `aware agent gc` on <date> because nothing referenced it; nothing else will be run in its place — compile the app again to use 0.1.6"; `app check` row gains `removed:{by:"gc", at}`; FloLess maps it to needs-you, never moves the workflow.
- Output `aware.agent-gc/v1`: `{applied, deferred?, recovery-window, complete, removed[], kept[+reasons], in-window[+until], skipped[], pending-delete[], stale-leases-removed, blockers[]}`; outcomes are data; `ok:false` only for `E_AGENT_GC_REFS_INCOMPLETE`, `E_AGENT_GC_REFERENCED` (`--only`), IO failures.

## 5. Guarantees preserved

- #626 determinism: GC never modifies a package (atomic whole-package rename only); runs still verify at preflight; dispatch reads only the leased catalogue; a GC'd pin → refusal, never fallback; leased packages can't be removed; the store-lock interlock means nothing is removed between verification and lease. R1/R3 close the partial-working-copy hole for version-only locks.
- #628: GC never reads/writes `<app>.lock` for approval purposes, never touches candidates/archives/HOLD, never promotes/reverts/moves a pin. The original approval RECORD is never deleted (only package bytes after the window). PR3b promotion must hold `RefGuard` shared while verifying targets and swapping the lock (to be written into the PR3b plan). Active runs never move; leases keep their bytes present.

## 6. Tests (TDD)

Swap: fault injection after each step → `agents/<id>` is always a complete old or new tree, recovery finishes/rolls back (byte-identity via `tree_bytes`); incoming-rename failure restores outgoing; concurrent updates of one id serialize; `discover_agents_in` never lists `.aware-swap`; version-only lock never snapshots a partial tree (R1 regression).

## 8. Round-1 Codex revisions (override earlier sections)

- **One lock order everywhere (R1-1).** Every path that needs both takes the **store lock first, then swap locks** (sorted): install, update, uninstall, synthesized-agent writes, swap recovery, run preflight, compile, migrate. GC takes store exclusive (try) and never a swap lock. Guard test: a source scan asserts no swap-lock acquisition site is reachable without a held `RefGuard` (the swap-lock API takes `&RefGuard`), with a negative control.
- **Readers recover before probing (R1-2).** Run preflight and compile, on finding a pending txn for an id (`agents/.aware-swap/<txn>/intent.json` naming it) or a missing `agents/<id>` with a txn present, take that id's swap lock **exclusive** briefly and run recovery, then continue with shared. Recovery never needs doctor or another writer.
- **Journaled multi-id swaps (R1-3).** `intent.json` lists the sorted id set; each move appends a durable journal line (`moved-out <id>`, `moved-in <new_name>`, `rolled-back <id>`) with fsync of the journal and the parent dir after each rename. Recovery replays the journal: if `moved-in` is recorded and `agents/<new_name>` hashes to incoming-digest → commit (drop outgoing copies, delete txn); otherwise roll back every recorded `moved-out` in reverse and drop incoming. All swap locks of the set are held until recovery completes. Fault tests after every journal line.
- **Guard before reading the approval (R1-4).** `app run` takes `RefGuard::shared` **before** reading the source and `<app>.lock` and holds it through final catalogue resolution and lease creation; same for compile (before reading source through `write_lockfile`) and every migrate verb.
- **Legacy version-only locks (R1-5) — rejected again.** Refusing them would break every existing locally-installed workflow on upgrade with nothing for the person to act on; #626 already decided they keep today's version-only guarantee, labelled `approval: version-only` / `current-version-only`, and never resolve to an older store package. What this plan fixes is the *partial-tree* hole (R1/R3 above): a version-only run now only ever snapshots a complete, swap-locked working copy. Recompiling upgrades them to digest approval.
- **Older CLIs on the same home (R1-6) — narrowed.** No barrier exists that 0.149/0.150 would honour, so a hard refusal would make GC unusable on any home that ever ran them. Instead: (a) GC removes `.tmp-*` only when older than 1 hour (an active snapshot by any CLI finishes in seconds; deleting a live temp only fails that snapshot, never yields other bytes); (b) the residual risk is stated precisely in the spec: a run by AWARE 0.149/0.150 (no lease) whose own lock is replaced or uninstalled mid-run, and which outlives the recovery window (30 days), can lose its package — it then fails, never runs other bytes; (c) `gc --apply` prints that note when any `apps/` lock was compiled by `compiler-version` < this release; (d) FloLess version-gates its own calls.
- **Every reference mutation under the shared guard (R1-7):** root add/remove (atomic write published before release), `app install/uninstall/rename/duplicate`, compile, `migrate prepare/discard/hold/unhold/promote/revert`, archive writes. Guard test lists the writers of every reference kind (source scan + negative control).
- **Unreadable/malformed lease or lock-probe error → table incomplete (R1-8)**; GC removes nothing.
- **Stamps serialized and part of the operation (R1-9).** Per-digest stamp update takes `refs/<id>/<hex>.lock` exclusive, reads, writes max, releases. Lease drop deletes the lease file only **after** its stamps are written; if stamping fails the stale lease file stays and GC treats its packages as `recent` from the lease's `started-at`/file mtime (the stale lease is evidence, removed only after its stamps succeed). For lock replacement / uninstall_app / discard the stamp is written before the commit step; a stamp failure fails the operation before anything changes.
- **Lock enumeration mirrors run resolution (R1-10).** For each discovered app dir the scan enumerates every `*.lock` sidecar, pairs it with its source exactly as `resolve_app_dir`/`load_approved_app_with_lock` do (by name and by the source's `app:` field), and marks the table incomplete on an unpaired lock, two sources claiming one app id, or an unrecognized layout. A test uses an app whose dir name differs from its `app:` field.
- **PR gating (R1-11) — narrowed.** #627-a ships with the fixed lock order. #629-b (GC apply) may merge only if either (i) no promotion verb exists in AWARE yet (#628 PR3b unmerged), or (ii) PR3b's promotion holds `RefGuard` shared while verifying targets and swapping the lock; whichever of #629-b / PR3b merges second carries the integration test "GC racing promotion". #629-b also requires the reference-writer audit test from R1-7 to pass.

## 9. Round-2 Codex revisions

- **Binding rule restated precisely (R2-1).** The rule this plan protects is the one #626 shipped: *a run executes exactly the bytes its lock approved — the recorded digest where the lock records one (`agent-digests` / `agent-bundle-pins`), and for a legacy lock that records only a version, a complete, swap-locked snapshot of the working copy carrying that version, labelled `approval: version-only` and never resolved to an older store package.* My round-0 wording ("never bytes other than its lock's digests") overstated it. Refusing version-only locks is a product change (it would break every existing local-folder workflow on upgrade), decided in #626 and out of scope here; GC never deletes the working copy, so it cannot affect version-only runs at all.
- **Older CLIs: a mechanism they already honour (R2-2).** Every AWARE run since long before 0.149 writes a JSONL trace under `logs/<app>/<instance>/<run-id>.jsonl` with a `run-start` event (carrying `cli-version`) and a `run-end` event. `gc --apply` scans traces whose `run-start` is within the recovery window: any run **without `run-end`** that has no lease file (i.e. a CLI older than the lease release, or a crash) blocks deletion of every package that run could have resolved — its app's current lock's pins and every archived pin of that app within the window — reported as reference kind `unfinished-run` (with app, run-id, started-at, cli-version). An unreadable trace in the window → table incomplete. A crashed run's trace ages out after the window. Residual risk: a run older than the window that is still running without a lease — documented, and GC prints the oldest unfinished trace it ignored.
- **Pending-step journal (R2-3).** Before each rename the swap writes and fsyncs a `pending <op> <from> -> <to>` line; after it, `done <op>`. Recovery reconciles every `pending` without `done` by inspecting the actual paths and digests (source present/destination absent → not done; destination present with the expected digest → done) before replay/rollback.
- **Whole-transaction recovery (R2-4).** A reader that finds a pending txn reads its `intent.json` first and acquires **every** id in the txn's sorted set (exclusive, after the store lock) before recovering; only then takes its own shared lock.
- **Stale leases block until stamped (R2-5).** A stale lease file whose packages have no durable end stamp is a **blocking** reference (`stale-lease-unstamped`), not `recent`. GC itself, under the exclusive store lock, writes the end stamp (= now) for each such package durably, then deletes the lease file; the window starts from that stamp. A failure to write it leaves the lease file and keeps blocking.

## 10. Round-3 Codex revisions — the unfinished-run rule, exactly

Replaces R2-2's mechanism:
- **Classification by content, not version (R3-3).** A trace's `run-start` either carries `agent-resolution` (written by every store-aware CLI, ≥ 0.149 / #626) or not. *With* it: the run's exact resolved packages are known (`{agent: {version, digest, resolution}}`, plus nested entries). *Without* it: the run was made by a CLI that predates the store and dispatched from `agents/<id>` — it holds no store reference, so GC cannot affect it. An unparseable `run-start` (or an unreadable trace file) → table incomplete. Tests use real trace fixtures written by 0.148 (no resolution) and 0.149/0.150 (resolution), captured from the released CLIs.
- **Use the run's recorded digests (R3-1).** An unfinished run (`run-start`, no `run-end`) without a live lease keeps exactly the digests in its `agent-resolution` (and nested entries) — reference kind `unfinished-run` — never reconstructed from the app's current lock or archives.
- **No age cut-off (R3-2).** An unfinished, unleased run keeps its packages **indefinitely** — until its trace gains `run-end`, or a person explicitly releases it with `aware agent gc --forget-run <run-id>` (an ask; recorded in the GC output and in the trace directory as `<run-id>.forgotten` with who/when). GC lists every such run under `unfinished-runs` so the front door can show "this run never finished — release it?". A crash leaves such a trace forever until released, which costs only disk, never correctness.

## 11. Round-4 revision — an enforceable barrier against unguarded CLIs (replaces sections 9 R2-2 and 10)

The trace-based "unfinished run" mechanism and `--forget-run` are **deleted**. Instead, the store moves:

- **`agent-store-v2/` is the only store GC ever touches.** The release that introduces leases (#627-b) switches every store reader and writer to `AWARE_HOME/agent-store-v2/` (same layout as #626). AWARE 0.149/0.150 (the only unguarded store-aware CLIs) have `agent-store/` hard-coded and never read `agent-store-v2/`, so nothing they do can depend on a package GC removes — the barrier is structural, not inferred.
- **Legacy `agent-store/` is never deleted or modified by any new CLI** (and never by GC). It remains the private store of any older CLI still used on the home.
- **One-time import:** on first store access, a new CLI imports every verified legacy package into `agent-store-v2/` (copy into a same-dir temp, verify digest + receipt key, publish — the existing `snapshot` publication path), under the exclusive store lock. A package that fails verification is not imported (reported). Idempotent; a marker `agent-store-control/imported-from-legacy` records it, and later legacy packages (written by an older CLI afterwards) are picked up by a re-import whenever the legacy dir's listing changes (cheap stat check).
- **Older CLI after the switch:** it runs exactly as before against its own `agent-store/` (and may snapshot new packages there); none of its runs can be affected by GC. A lock compiled by an older CLI is readable by the new one (same digests; the import supplies the bytes).
- **Liveness is only needed for new CLIs**, whose leases are OS locks (section 2) — established without inference. `stale-lease-unstamped` (R2-5) stays.
- Disk: the legacy store is duplicated once into v2 (hard links are NOT used: a hard link would let an older CLI-side change alias v2 bytes). GC reports the legacy store's size under `legacy-store` so a person can delete it by hand once no older CLI is used.
- Tests: an older-CLI fixture (a copy of the 0.150 resolver behaviour, or the released 0.150 binary in the E2E) running against the same home while the new CLI GCs v2 → the old run is unaffected; import idempotence; corrupt legacy package not imported; legacy dir byte-identical after every new-CLI command.

## 12. Round-5 Codex revisions (final)

- **Import never upgrades a held guard (R5-1).** `RefGuard::shared` is only obtainable through `store::open(paths)`, which first checks whether an import is needed and, if so, takes the store lock **exclusive** (blocking, before any guard is held by this process), imports, releases, and only then acquires shared. No code path holds a shared guard while asking for exclusive; a debug assertion + a test enforce it.
- **Legacy rescan, not a root stat (R5-2).** The change check walks the legacy package tree (`agent-store/<id>/<hex>/<key>` — three levels, names only, cheap) and compares it with the import record; in addition, whenever a requested digest is missing from v2 the resolver triggers an import pass for that agent before reporting `pin-not-installed`.
